# 多设备常驻连接：下一批实现设计与验收

日期：2026-11-09。状态：**设计，尚未实现**。本批代码工作为签名发布检查、布局方案保存和精密滚动；本文件不表示网络层已经支持多设备同时在线。

## 目标与范围

下一批先完成本机作为中心、与多台已经认证的 Windows/Mac 保持连接，用户切换目标时复用连接；本机输入捕获和注入各只有一份，同一时刻最多存在一段实际输入控制关系。第一阶段沿用现有四向直接邻居模型，一侧最多一个邻居，保存但未摆放的设备没有边缘入口。布局方案仅保存偏好，不赋予信任，也不代表在线。

这不是 Oink 的全组焦点协议：A 同时连接 B/C 并不意味着 B 与 C 互相连接，也不提供 B→C 的输入转发、成员组播、跨组焦点共识或公网中继。不能在缺少相应协议和验收时宣称“任意设备全组互控”。Linux 仍按用户选择暂缓。

## 当前代码与契约边界

| 位置 | 当前行为 | 下一批需要拆开的边界 |
|---|---|---|
| `crates/app/src/daemon.rs::run_async` | 建一条连接、认证、执行会话、断开后全局重试 | 常驻端点/发现、逐设备拨号和重连、认证准入、唯一输入协调器 |
| `daemon.rs::run_session` | 一次拥有捕获、注入、Engine、控制流、心跳、权限检查、剪贴板接收任务 | 平台运行时进程唯一；网络连接独立持有流与心跳 |
| `daemon.rs::establish_conn` | 手动连接时随机本地端口；成功后关闭发现 | 始终监听配置端口并广播；手动地址仅是拨号候选 |
| `crates/app/src/status.rs::ConnStatus` | 单个连接、地址、指纹、RTT、配对请求 | 逐设备连接快照和独立焦点身份，保留托盘汇总接口 |
| `crates/app/src/clip.rs::spawn_receiver` | 每连接的任务直接写系统剪贴板，拥有独立文件归批状态 | 中心授权令牌和最终写回校验，阻止闲置/过期来源覆盖 |
| `crates/app/src/ui/device_catalog.rs` | 切换/添加设备都停止并重启整个 daemon | 向常驻协调器发命令，目标变化不重建其他连接 |
| `crates/core/src/engine.rs::feed_peer` | `ReleaseAll` 无条件产生平台释放动作 | 非焦点来源必须在外层拒绝，不能让闲置 Engine 操作公共注入器 |

SPEC 当前修订明确“单次一个活动会话，切换必须结束旧会话”。实施常驻多连接时须同步修订为“多个认证连接、一个输入焦点”，记录用户已授权的范围，并同步 DEVELOPMENT、设备清单注释和界面文案。协议版本、默认 UDP 53728、mDNS 类型、TLS 指纹 pinning 不应被顺手更改。

当前实际输入、控制与心跳共用可靠持久 QUIC 流；Datagram 是现有原语但尚未接入实际输入。此次不同时迁移传输通道，以便把新增问题定位在多设备协调层。

## 运行时所有权

建议保留 `ms-net` 的 Endpoint/Conn 原语，分离下列责任；具体文件可在实施时再拆，接口职责不可混合。

| 所有者 | 独占资源 | 输出/输入 |
|---|---|---|
| 常驻网络管理器 | Endpoint、Discovery、候选地址、逐 peer Backoff、连接代数 | 候选连接交准入；已认证连接交协调器 |
| 单个准入队列 | 配对 UI 请求、信任列表读改写、拒绝日志集合 | 一次一个人工 SAS；保存成功后才交出已认证连接 |
| 每 peer 链路 | Conn、控制收发流、屏幕信息、HeartbeatTracker、发送队列、链路代数 | 带完整 PeerId 与链路代数的消息/断线事件 |
| 唯一输入协调器 | InputCapture、InputInject、捕获队列、焦点、各 peer Engine、权限/电源检查 | 执行平台动作；按焦点向对应链路发控制消息 |
| 剪贴板授权器 | 剪贴板写入顺序、焦点令牌、跨来源归批代数 | 接收开始和最终写回两次校验；允许保存文件与允许写剪贴板分别判断 |

不能并发启动多个现有 `run_session`。Mac tap、Windows hook、grab、注入按键集合都是进程共享的系统状态；任一闲置会话调用 cleanup 或 `release_all` 会破坏当前焦点。

每个链路事件必须携带 `(完整指纹, connection_generation)`；移除、替换和关闭都比较代数。旧连接迟到的接收消息、发送失败和 close 事件，不得作用于同指纹的新连接。队列必须有容量上限，控制流拥塞须产生明确故障事件；不能无限堆积输入或静默丢掉抬键。

## 准入、发现与身份

1. 常驻监听和发现与主动拨号并存。监听端口使用实际配置端口；广播端口来自 Endpoint 的实际监听值。地址归一化仍复用现有 IPv4/端口校验。
2. mDNS 的短 ID、名称、地址都只是未认证候选。连接后必须校验完整 TLS 指纹与期望的已保存身份；发现前缀不得成为授权依据。
3. 同一设备同时出入站连接要有确定性去重。优先沿用双方指纹次序决定主动拨号方向；手动拨号与发现同时触发也须最多保留一条已认证链路。替换时不得误关闭当前胜出的连接。
4. 先并行完成网络握手，再将需要人工配对的候选送入单个准入队列。配对请求绑定指纹、链路代数和请求 ID；确认只作用于所显示请求，过期确认不可批准下一台设备。
5. `check_trust` 现在是读文件、修改、写回。并发执行会丢失另一台刚加入的信任。因此准入与撤销必须由一个写入者串行处理，失败不降级为空信任或 TOFU；撤销完成后才能删除 UI 清单记录。
6. 添加新设备不能关闭已有会话，但“添加模式”也不能让所有陌生连接自动进入输入会话。未知指纹仍需显式添加和双方人工 SAS 确认；已信任连接可继续心跳和工作。
7. 保存的重连地址应为已验证设备的监听地址。不能直接将入站连接的 `remote_addr()` 临时源端口当成固定监听端口。仅发现信息与实际 TLS 身份对应后更新候选；没有可靠监听地址时保留自动发现，不伪造地址。

## 焦点与安全事务

焦点至少区分本机空闲、向某 peer 输出、本机受某 peer 控制、切换中。每次进入/退出推进 `focus_generation`，并保存关联链路代数。

- 本机输入只喂给当前焦点 Engine，或在本机空闲时由明确的四向边缘路由选择一个已连接邻居；不能把同一按键广播给所有 Engine。
- 在本机空闲时接收一个有效 `EnterScreen` 才能建立被控关系。已存在焦点时，其他 peer 的进入请求拒绝并回复有界 `ReleaseAll`/`LeaveScreen`；后续输入也拒绝。
- 非焦点来源的 Key/Mouse/Scroll/**ReleaseAll** 不得调用公共注入器。来自错误代数的 Leave/断线不能解除当前 grab。
- 同一 peer 的双方同时发起控制可复用已有指纹优先级；跨 peer 的竞争由中心协调器串行裁决。此规则仅约束本机，不冒称全组共识。
- 目标切换先执行旧 Engine 的安全返回动作：本机先解除 grab、释放按键、恢复光标，然后有界通知旧 peer 释放；完成后才能启用新焦点。网络等待不能挡住本机解除拦截。
- 焦点 peer 断开时立即恢复本机，不自动选择另一台设备。闲置 peer 断线只更新其状态和独立重试，不能调用全局 cleanup 或取消所有传输。
- 进程暂停、权限撤销、捕获失效和退出才执行一次全局 `session_safety::cleanup`，保持 TECH-REVIEW A-1/B-2 的固定顺序，并停止全部后台任务。睡眠/显示排列变化重建输入坐标时先安全回到本机。

### v1 协议的切换边界

现有输入消息没有焦点代数，也没有显式“已释放”确认。仅在本地切换一个指针，不能证明旧 peer 的在途输入已经耗尽。第一条实现不得忽略此窗口。

可评估复用可靠控制流的次序，发送 `ReleaseAll → LeaveScreen → 带唯一 seq 的 Ping`，等待同一链路对应 Pong 作为释放屏障。接收端必须在处理 Leave 的平台释放之后再回复该 Ping；所有输入和 Pong 必须保持同一可靠流顺序，不能由另一个任务越过释放事务。协调器在屏障完成前不得重新激活同一链路；屏障超时就关闭这条旧链路，而其他链路保持常驻。此候选方案必须通过乱序调度/拥塞回环验证，不能只凭 QUIC 有序便视为完成。

如果现有旧版对端无法保证这个屏障，或后台发送会越过它，则 v1 兼容路径应关闭并重连旧 peer，清空在途状态。要做到带会话代数的完整焦点协商需另行设计协议扩展；不能修改现有载荷后仍声称与 0.2.2 完全兼容。

## 剪贴板与文件授权

现有两端切换关系结束时会发送剪贴板，因此接收许可不能简单等同“此刻 Engine 为 Controlled”。但也不能让所有在线 peer 永久有权覆盖系统剪贴板。

每次允许同步产生绑定 `(PeerId, connection_generation, focus_generation)` 的令牌。接收首帧记录令牌，重组完成、确认正常 FIN 后，在同一写入临界区再次校验。下一次焦点关系、新的复制内容或撤销信任使旧令牌失效。对应的结束关系可保留令牌至下一次焦点变更，允许其正常返回剪贴板；无关联关系的闲置来源拒绝。

文件传输和剪贴板写回分开：已授权且用户接受的传输可继续落地到接收目录，但其过期完成结果不能覆盖新焦点的剪贴板。归批 ID、剪贴板序号和焦点代数都应参与最终判断；跨 peer 的文件不能仅凭“两秒内到达”归到同一批。

当前文件 UI/传输中心仍是全局接口，实施时先保持“有活动传输则阻止手动焦点切换”的现有规则。不要为了演示多设备切换而删除限制；允许后台跨设备传输须同时给进度、取消和授权补充来源身份，再独立验收。

## 完成与发布边界

只有 B/C 真实同时连接、焦点隔离测试通过，才能写“多设备同时在线”；只有端到端复用链路测试通过，才能写“切换无需重连”。本文件及布局方案功能本身都不满足这些条件。签名证书、公证和上传仍按各自发布任务验证；多设备实现不应顺便替换当前已授权的 Mac 安装包或重置 TCC。
