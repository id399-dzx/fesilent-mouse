# 精密滚动的小数保留（F-1022）

2026-11-09。修复慢滑触控板时小幅位移逐帧被取整吞掉的问题，不等同新增完整多指手势、惯性阶段协议或Windows精密触控板注入。

## 复现与修复

修复前，核心倍率1.5×收到`precise=true, dy=0.25`时输出0.0；复现测试先失败，期望每帧0.375。Mac注入又把每帧像素四舍五入为整数；Windows把每帧乘120后独立四舍五入，也会丢掉更小增量。

现在核心对精密滚动直接保留倍乘后小数，横向保持原量；普通滚轮保留原有整格倍率语义。共享无锁/无分配的每轴余量器只在系统API整数边界量化：Mac像素/行、Windows的WHEEL_DELTA单位分别适配。

- 连续十帧`dx=0.2,dy=-0.3`最终累计`(2,-3)`，中间轨迹量不再永久丢失。
- 各轴独立；方向反转丢弃该轴旧余量，普通/精密模式切换清空，`release_all`/会话结束清空，不把上个会话余量带入新会话。
- 非有限输入忽略并清理对应轴余量，过大输入饱和，余量保持有界。
- 协议仍为既有Scroll的dx/dy/precise，无新增消息、依赖或捕获权限。

## 验证

新增9项回归：核心精密倍率逐帧小数、模式切换；平台双轴慢速累计、Windows小于1个wheel单位累计、单轴反转、普通滚轮与模式切换、释放重置、非有限值、整数饱和。核心原有普通滚轮倍率矩阵/反转热切换仍通过。

全workspace293项通过、0失败、9项原有忽略；Mac与Windows严格Clippy/release构建通过。证据日志在`target/oink-batch-tests.txt`、`target/oink-batch-*-clippy.txt`和`target/oink-batch-*-build.txt`。

待H-2/H-5双机真机：Mac触控板慢滑/快滑/横向/反转，倍率1.0与1.5；Windows普通滚轮一格与横向滚动；切换/暂停后首个事件无旧余量。不把跨平台编译与纯逻辑测试当成真实触控板体验验收。
